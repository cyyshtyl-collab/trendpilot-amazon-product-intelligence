# TrendPilot 亚马逊选品情报工作台

TrendPilot 是一个面向选品负责人和小型跨境团队的决策工作台。当前版本无需外部服务即可运行，使用内置演示数据展示完整的选品路径，并为后续数据源、AI 工作流和自动推送保留稳定边界。

## 运行

```bash
npm install
npm run dev
```

打开终端显示的本地地址。生产构建使用 `npm run build`。

## 四阶段架构

1. **数据采集**：首版支持手动创建候选；升级时由卖家精灵 API、八爪鱼或 Octoparse 写入统一的产品、Listing、评论和关键词结构。
2. **趋势分析**：界面消费统一的月度搜索与社媒信号；升级时可由飞书多维表格或 Airtable 作为长期数据库，避免页面依赖具体供应商字段。
3. **AI 评分与卖点提炼**：五维评分和结论字段已固化；升级时将当前演示结果替换为 Coze 或 Dify 工作流返回的结构化 JSON。
4. **决策产出**：候选排名、详情与卖点草稿已经形成输出层；升级时由 n8n 或 Make 定时生成周报并推送飞书或企业微信。

## 稳定数据契约

产品记录至少保留：产品名称、类目、站点、六个月搜索趋势、Top 20 评论分布、好评摘要、差评摘要、BOM 成本、预估售价、起订量和打样周期。

评分结果固定为五项 1–5 分：需求真实性、竞争可切入度、差异化空间、供应链可控性、双线协同性。总分 18–25 为“通过”，15–17 为“观察”，低于 15 为“淘汰”。下游只依赖这一标准结果，不直接依赖 GPT、Claude、Coze 或 Dify 的供应商格式。

## 推荐升级顺序

先接入飞书多维表格或 Airtable，建立长期数据主表；再接卖家精灵与评论采集；随后接 Coze/Dify 的评分 JSON；最后用 n8n/Make 做每周调度和消息推送。这样每一步都能独立验证，也不会让采集、评分和通知互相耦合。

## 自动商品数据源

在生产环境设置 `CANDIDATE_FEED_URL` 为可公开下载的 HTTPS CSV 地址，并可用
`CANDIDATE_FEED_NAME` 标记渠道名称。服务器每 6 小时下载一次，单次最多导入 500
条、5MB；必须包含“产品名称”和“ASIN”，其余字段兼容页面下载的标准模板。
记录按 `ASIN + 站点` 增量更新，并自动形成每日快照与采集日志。
